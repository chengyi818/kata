# Test-Driven Development

## 作用

经典 TDD 循环：先写测试 → 看它失败 → 写最少代码让它通过 → 重构。适用于所有功能开发和 bug 修复。

## 铁律

**没有先写测试就写实现代码？删掉重来。**

## TDD 循环

```
RED    → 写一个失败的测试
GREEN  → 写最少的代码让测试通过
REFACTOR → 消除重复，改善结构
```

## 为什么必须先看测试失败

如果你没看到测试失败，你不知道它是否真的在测正确的东西。通过的测试可能是假阳性。

## 适用范围

- ✅ 新功能
- ✅ Bug 修复
- ✅ 重构
- ✅ 行为修改
- ❌ 一次性原型（需用户批准豁免）
- ❌ 配置文件
- ❌ 生成的代码

## 嵌入式场景

- 驱动单元测试
- 内核模块功能验证
- 交叉编译后的回归测试
