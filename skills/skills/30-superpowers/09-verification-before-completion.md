# Verification Before Completion

## 作用

在声称任何工作完成、bug 修复、测试通过之前，必须先运行验证命令，拿到真实证据。

## 铁律

**没有验证证据就没有完成声明。** 声称完成但没验证 = 不诚实。

## 流程

1. **明确验证目标** — 什么命令能证明这件事完成了？
2. **运行完整验证** — 跑 lint、typecheck、测试等
3. **确认输出** — 检查命令的实际输出
4. **基于证据声明** — 拿到结果后才能说"完成了"

## 常见违规

| 错误做法 | 正确做法 |
|---------|---------|
| "应该没问题了" | 运行 `npm run test` 看结果 |
| "我检查过了" | 刚才跑的什么命令？输出是什么？ |
| "改动很小不需要测试" | 跑一下 lint 确认 |

## 适用场景

- 任何任务声称完成前
- 提交代码 / 创建 PR 前
- 修复 bug 后
- 重构完成后

## 嵌入式场景

- 交叉编译后验证二进制
- 驱动修改后运行硬件测试
- 内核配置变更后编译验证
