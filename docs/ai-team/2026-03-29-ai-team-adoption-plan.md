# 嵌入式研发团队 AI 工具推广实现计划

> **For agentic workers:** 本计划将设计文档中的策略拆解为可执行的具体任务。

**Goal:** 年底 80% 成员熟练使用 opencode，研发效率提升 30%+

**Architecture:** 种子团队先行，Q2 深度试用 → Q3 传帮带 → Q4 全员覆盖 + 制度化

**Tech Stack:** opencode CLI + 公司 API + Git 知识库

---

## Phase 0：准备阶段（第 1-2 周）

### Task 0.1：建立知识库仓库

**产出：** 团队 AI 知识库 Git 仓库

- [ ] **Step 1：创建仓库结构**

```bash
mkdir -p team-ai-knowledge/{skills,docs,faq,training}
mkdir -p team-ai-knowledge/skills/{requirement,design,coding,testing,debug,cve}
```

- [ ] **Step 2：编写 README**

内容包括：
- 仓库用途说明
- 目录结构说明
- 贡献指南（如何提交 skill、如何提 PR）
- 使用说明（如何在 opencode 中配置 skill 路径）

- [ ] **Step 3：初始化 .gitignore 和 LICENSE**

- [ ] **Step 4：提交并推送到内部 Git 服务**

```bash
git add -A && git commit -m "init: 团队 AI 知识库初始化" && git push
```

### Task 0.2：选拔种子团队成员

**产出：** 种子团队名单

- [ ] **Step 1：制定选拔标准文档**

明确 4 个维度：技术意愿、技术覆盖、影响力、学习能力

- [ ] **Step 2：与候选人一对一沟通（每人 15-20 分钟）**

说明项目背景、时间承诺（每周约 2-3 小时额外投入）、激励机制

- [ ] **Step 3：确定 5-6 名种子成员，明确各人认领的场景**

场景分配表（每人 1-2 个）：

| 成员 | 认领场景 |
|------|----------|
| 成员 A | 需求分析 |
| 成员 B | 设计文档 |
| 成员 C | 代码开发 |
| 成员 D | 测试用例 |
| 成员 E | 问题定位 |
| 成员 F | CVE 修复 |

- [ ] **Step 4：建立种子团队沟通群（企微/飞书群）**

### Task 0.3：采集全员基线数据

**产出：** 基线数据表

- [ ] **Step 1：设计基线采集表**

| 场景 | 任务描述 | 当前耗时（小时） | 备注 |
|------|----------|-----------------|------|
| 编码 | 实现一个中等复杂度内核模块 | | |
| 文档 | 从零编写一份模块设计文档 | | |
| 测试 | 为一个模块编写完整测试用例 | | |
| 定位 | 分析一个内核 oops 到根因 | | |

- [ ] **Step 2：全员填写基线数据（1 周内完成）**

- [ ] **Step 3：汇总分析，建立基线档案**

## Phase 1：种子团队深度试用（Q2，第 3-10 周）

### Task 1.1：种子团队启动会

**产出：** 启动会议纪要、明确的个人计划

- [ ] **Step 1：召开启动会（1 小时）**

议程：
- 项目背景和目标回顾
- 种子团队职责说明
- 各人认领场景确认
- 第一周行动计划
- 沟通机制和节奏确认

- [ ] **Step 2：每人制定个人 Q2 试用计划**

包含：每周使用频次、重点攻克场景、预期产出

### Task 1.2：场景 skill 开发（持续迭代）

**产出：** 6 个核心场景的初始 skill

每个种子成员为自己认领的场景开发 skill：

- [ ] **Step 1：调研场景需求**

收集该场景下的典型任务、常见问题、需要的上下文信息

- [ ] **Step 2：编写初始 skill**

格式参考 opencode skill 规范，包含：
- 场景描述和触发条件
- 详细的工作流程指引
- 关键 prompt 模式
- 领域知识注入（内核 API、虚拟化概念等）

- [ ] **Step 3：在实际工作中试用，记录效果和问题**

- [ ] **Step 4：根据反馈迭代优化 skill**

- [ ] **Step 5：提交到团队知识库，发起 PR**

```bash
git add skills/xxx/skill-name.md
git commit -m "feat: add xxx 场景 skill v1"
git push
```

### Task 1.3：每周分享会（持续）

**产出：** 分享记录、FAQ 更新

- [ ] **每周 Step 1：种子成员轮流分享（15-30 分钟）**

内容：本周使用心得、踩坑经验、prompt 技巧、skill 迭代

- [ ] **每周 Step 2：记录分享要点，更新 FAQ 文档**

### Task 1.4：编写使用 SOP

**产出：** 各场景标准化操作流程

- [ ] **Step 1：每个场景编写 SOP 文档**

内容包括：
- 适用场景和前置条件
- 操作步骤（如何启动 opencode、如何加载 skill、如何输入上下文）
- 常见问题和解决方案
- 最佳实践和注意事项

- [ ] **Step 2：种子团队内部评审 SOP**

- [ ] **Step 3：提交到知识库 docs/ 目录**

### Task 1.5：Q2 阶段总结

**产出：** Q2 总结报告

- [ ] **Step 1：收集种子团队 Q2 使用数据**

- [ ] **Step 2：编写 Q2 总结报告**

内容：
- 各场景 skill 成熟度评估
- 效率提升初步数据（对比基线）
- 遇到的主要问题和解决方案
- Q3 传帮带计划建议

- [ ] **Step 3：向全员汇报 Q2 成果**
