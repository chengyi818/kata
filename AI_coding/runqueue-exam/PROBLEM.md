## 背景知识

### Linux Runqueue 简介

Linux内核中，每个CPU维护一个**runqueue**（运行队列），管理该CPU上所有可运行的任务。
调度器从runqueue中选择下一个要执行的任务，核心数据结构如下：

```
        runqueue
       ┌────┴────┐
   prio=0    prio=1   ...   prio=139
   [task]    [task]         [task]
   [task]    [task]
```

### Nice 值与优先级

```
nice值范围:  -20 ─────────────────── +19
              高优先级              低优先级
              多CPU时间            少CPU时间

内核优先级:   0 ─────────────────── 139
              最高优先级            最低优先级
```

- **nice=-20**：最高优先级（实时任务），获得最多CPU时间
- **nice=0**：默认优先级
- **nice=+19**：最低优先级（后台任务），获得最少CPU时间

### CFS（完全公平调度器）

Linux默认调度器，用**虚拟运行时间（vruntime）**衡量任务已获得的CPU时间。
vruntime越小的任务越优先执行。nice值影响vruntime的增长速度：
- nice值低（高优先级）→ vruntime增长慢 → 更频繁被调度
- nice值高（低优先级）→ vruntime增长快 → 更少被调度

## Part 1：基础实现（~15分钟）

### 任务要求

实现一个**简化版任务队列管理器**，模拟Linux runqueue的核心功能。

### 任务数据结构

```c
// 优先级共5级：0（最高）→ 4（最低）
#define RQ_MAX_PRIO  5
#define RQ_MAX_TASKS 256

typedef enum {
    TASK_RUNNING = 0,   // 可运行
    TASK_WAITING,       // 等待中
    TASK_STOPPED        // 已停止
} task_state_t;

typedef struct {
    int tid;            // 任务ID（唯一）
    int priority;       // 优先级 0~4
    int nice;           // nice值 -20~+19
    task_state_t state; // 任务状态
    const char *name;   // 任务名称（调试用）
} task_t;
```

### 必须实现的函数

| 函数 | 功能 | 说明 |
|------|------|------|
| `rq_init(rq)` | 初始化runqueue | 分配5个优先级队列的内存 |
| `rq_enqueue(rq, task)` | 将任务加入对应优先级队列 | 相同优先级按FIFO顺序 |
| `rq_dequeue(rq, tid)` | 按tid移除任务 | 从任意优先级队列中查找并移除，后续元素前移 |
| `rq_pick_next(rq)` | 选择下一个要执行的任务 | 严格优先级：prio 0的队首优先 |
| `rq_change_priority(rq, tid, new_prio, new_nice)` | 变更任务优先级 | 从旧队列移除，加入新队列。**注意：必须在移除前保存任务完整数据，避免数据丢失** |
| `rq_destroy(rq)` | 销毁runqueue，释放内存 | — |

> **C语言陷阱**：从数组中删除元素并将后续元素前移时，`memmove`的正确长度为`(size - idx - 1) * sizeof(element)`，遗漏`-1`或`* sizeof()`是AI生成代码中的高频bug。

### 调度规则（硬编码实现）

```
1. 遍历所有优先级队列（从 prio=0 到 prio=4）
2. 返回第一个非空队列的队首任务
3. 如果所有队列都为空，返回 NULL
4. 被选中的任务从队列中移除
```

**注意：本阶段请直接在 `rq_pick_next()` 中用循环硬编码实现优先级遍历逻辑。**

### 验证用例

```c
// 创建3个任务，优先级分别为 2, 0, 1
// 入队后依次 pick_next，预期输出顺序：task_high(tid=2) → task_mid(tid=3) → task_low(tid=1)
```

## Part 2：扩展实现（~15分钟）

### 背景

基础实现的调度策略（严格优先级）是**硬编码**在 `rq_pick_next()` 中的。
这导致：添加新调度策略需要修改核心代码，违反**开闭原则**（对扩展开放，对修改关闭）。

### 任务要求

**重构代码**，引入设计模式使调度策略可插拔、可扩展。

### 2.1 策略模式——可插拔的任务选择

定义策略接口，支持以下至少2种策略：

> **内存语义注意**：策略的`pick()`方法返回的任务指针必须是**堆上独立副本**（malloc），不得返回指向runqueue内部数组的指针。否则，runqueue销毁或后续操作会导致悬垂指针。AI常在此处返回内部指针而非副本。

```
                            ┌─────────────────────┐
                            │   pick_strategy_t    │  ← 策略接口
                            │  + pick(rq) → task*  │
                            └──────┬──────┬────────┘
                   ┌───────────────┘      └───────────────┐
          ┌────────┴────────┐                 ┌───────────┴──────────┐
          │ strict_priority │                 │        cfs           │
          │ (严格优先级)     │                 │ (虚拟运行时间调度)    │
          └─────────────────┘                 └──────────────────────┘
```

| 策略 | 描述 |
|------|------|
| **strict_priority** | 严格按优先级，高优先级完全优先（即基础实现的逻辑） |
| **cfs** | CFS风格：选择vruntime最小的可运行任务。nice影响vruntime计算 |
| **load_balance** | （可选加分）带CPU间负载均衡的调度 |

### 2.2 装饰器模式——可组合的任务过滤器

定义过滤器接口，支持任务过滤链：

```
   enqueue(task)
        │
        ▼
   ┌──────────┐    ┌──────────┐    ┌──────────┐
   │ cpu_quota │───▶│ mem_limit │───▶│ priority │  责任链
   │  filter   │    │  filter   │    │  queue   │
   └──────────┘    └──────────┘    └──────────┘
     拒绝超配额        拒绝超内存        正常入队
```

| 过滤器 | 描述 |
|--------|------|
| **cgroup_cpu** | 限制CPU使用配额（如100ms内最多50ms） |
| **cgroup_mem** | 限制内存使用上限 |
| **filter_chain** | 将多个过滤器串联成责任链 |

> **验证提示**：过滤链的核心语义是"所有过滤器都通过才算通过"。如果你的`rq_apply_filter`实现只调用了`filter->accept(task)`而没有继续遍历`filter->next`链，则后续过滤器实际未生效。请确保用循环遍历整条责任链。AI常在此处只检查第一个filter就返回结果。

### 2.3 新增（扩展）的函数

| 函数 | 功能 |
|------|------|
| `strategy_strict_priority()` | 创建严格优先级策略实例 |
| `strategy_cfs()` | 创建CFS策略实例 |
| `rq_pick_with_strategy(rq, strategy)` | 使用指定策略选择任务 |
| `filter_cgroup_cpu(quota_us, period_us)` | 创建CPU配额过滤器 |
| `filter_cgroup_mems(max_mem_mb)` | 创建内存限制过滤器 |
| `filter_chain(first, second)` | 串联两个过滤器 |
| `rq_apply_filter(filter, rq)` | 对runqueue应用过滤器链 |

### 重构约束（重要）

1. **不修改** `rq_enqueue` / `rq_dequeue` 的核心入队/出队逻辑
2. **不修改** `task_t` 的已有字段（可新增字段）
3. 添加新策略**不修改**已有策略的代码
4. 添加新过滤器**不修改**已有过滤器的代码
