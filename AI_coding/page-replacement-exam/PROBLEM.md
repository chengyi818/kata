# 机试题目：Linux页面置换算法模拟器

## 题目背景

在Linux操作系统中，内存管理子系统负责管理物理内存的分配与回收。当进程访问的虚拟页面不在物理内存中时，会触发**缺页异常（Page Fault）**，内核需要从磁盘将缺失的页面加载到物理页框中。当物理页框已满时，内核必须根据**页面置换算法（Page Replacement Algorithm）**选择一个页面换出（evict），以便为新页面腾出空间。

页面置换算法的优劣直接影响系统性能——好的算法可以减少缺页次数，避免频繁的磁盘I/O。Linux内核中实际使用的页面置换算法经历了从LRU到Clock算法（第二次机会算法）的演进，现代内核使用多级LRU链表和活跃/非活跃页框分类机制。

本题目要求你实现一个**用户态的页面置换算法模拟器**，并在实现过程中体会良好的软件设计对代码可维护性和可扩展性的重要意义。

## 第一部分：基础实现（约15分钟）

### 任务描述

实现一个简化版的页面置换模拟器，满足以下要求：

1. **物理页框数量可配置**（默认4个），通过命令行参数或常量指定
2. **接收虚拟页号访问序列**作为输入，序列长度和内容均可配置
3. **实现至少一种页面置换算法**（FIFO 或 LRU，任选其一）
4. **模拟完整的页面访问过程**，对每次访问判断是否发生缺页
5. **统计并输出：缺页总次数、总访问次数、缺页率**（保留两位小数）
6. **程序必须正确处理异常输入**，不得崩溃或产生未定义行为，包括：
   - 页框数为0或负数
   - 访问序列为空
   - 页号为负数
   - 动态内存分配失败（`malloc`返回`NULL`）
   对以上情况应输出有意义的错误提示并安全退出。

> **注意**：如果选择实现LRU算法，页面**命中**（已在页框中）时也需要更新算法的内部状态（如访问时间戳或链表位置）。遗漏命中时的状态更新会使LRU退化为近似FIFO的行为——这是LRU实现中的高频错误。

### 输入格式

程序通过标准输入或硬编码数组接收访问序列。页号为正整数（0 ～ 65535）。示例输入：

```
帧数: 4
序列: 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1
```

### 输出格式

```
=== 页面置换模拟结果 ===
算法: FIFO
物理页框数: 4
访问序列长度: 20
缺页次数: 10
缺页率: 50.00%
```

> **验证数据**：使用序列 `1 2 3 4 1 2 5 1 2 3 4 5`，3个物理页框：
> - FIFO: 缺页 **9** 次
> - LRU（正确实现）: 缺页 **10** 次  
> - 若LRU命中时未更新状态，结果将与正确LRU不同——请自查。

> **思考题（请在设计文档中回答）**：如果后续需要新增Clock算法、LFU算法、Optimal算法等，你当前的代码需要修改多少处？请评估改动量。

## 第二部分：扩展实现（约15分钟）

### 任务描述

在基础实现的基础上，**重构代码**使其支持方便地添加新的页面置换算法。具体要求：

1. **将页面置换算法设计为可替换的策略组件**——不同算法共享统一接口
2. **实现至少2种算法**（在原有的基础上再新增至少1种，如Clock、Optimal）
3. **使用至少一种设计模式**（推荐策略模式 Strategy Pattern）
4. **体现SOLID原则**：
   - **开闭原则（OCP）**：添加新算法时不应修改已有算法代码
   - **依赖反转原则（DIP）**：模拟器核心逻辑应依赖抽象接口，而非具体算法实现
5. **代码结构清晰**，每个算法实现在独立文件中
6. **支持运行时选择算法**（通过算法名称字符串选择，如 `"FIFO"`、`"LRU"`）
7. **每个策略实例必须持有独立的内部状态**（如页框数组、访问计数器、引用位等），随实例创建而分配、随销毁而释放。**禁止使用全局变量或函数内`static`变量存储算法状态**——这会导致多个模拟器实例之间互相干扰，且无法在单进程中复用不同策略。

### 架构要求

你的代码结构应类似于：

```
模拟器核心
    |
    +-- 页面置换算法接口（抽象层）
        |
        +-- FIFO算法实现
        +-- LRU算法实现
        +-- Clock算法实现  （新增，不修改已有文件）
        +-- Optimal算法实现（新增，不修改已有文件）
        +-- ...未来可能更多
```

## 提示

- **C语言建议使用函数指针表（vtable模式）模拟多态**，这正是Linux内核VFS等子系统使用的惯用法
- 如果选择C++/Rust等语言，请利用语言原生的多态机制（虚函数/trait）
- 注意内存管理：所有通过`malloc`分配的内存必须在程序结束前`free`
- **不要过早过度设计**：基础部分保持简单，扩展部分再重构——这恰好展示了从"能用"到"好用"的工程演进过程
- 如果你的光标在15分钟时基础部分已经具有良好的抽象，那么扩展部分应该只需要5分钟——这是一个很好的信号
