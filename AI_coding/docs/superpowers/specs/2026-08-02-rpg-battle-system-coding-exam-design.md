# RPG战斗系统 — AI辅助编程机试题设计

## 概述

**场景领域**：RPG角色扮演游戏  
**题目结构**：1个基础任务 + 3个独立可选扩展（1+N结构）  
**目标考生**：初级工程师  
**预计耗时**：基础15分钟 + 每扩展15分钟  
**默认语言**：Python（框架支持C++/Python/Java三语言）  
**输出件**：需求澄清文档 + 设计文档 + 测试用例 + commit记录（白盒交付）

---

## 设计模式覆盖

| 设计模式 | 所在位置 | 考察点 |
|----------|----------|--------|
| 模板方法 (Template Method) | 基础任务 | 战斗流程骨架设计，钩子方法预留扩展点 |
| 策略模式 (Strategy) | 扩展1 | 攻击方式算法族封装，OCP实现 |
| 工厂模式 (Factory) | 扩展2 | 装备类型创建，与装饰器区分 |
| 装饰器模式 (Decorator) | 扩展2 | 装备前缀/属性增强，组合优于继承 |
| 责任链模式 (Chain of Resp.) | 扩展3 | 战斗效果链处理，可插拔可排序 |

## SOLID原则覆盖

| 原则 | 核心考察点 |
|------|-----------|
| SRP 单一职责 | 伤害计算、日志输出、效果处理分离到不同类 |
| OCP 开闭原则 | 新增攻击方式/装备/效果不修改现有代码（每个扩展的核心考核点） |
| LSP 里氏替换 | 策略接口、Handler接口的子类可互相替换，不改变契约 |
| ISP 接口隔离 | 策略接口仅 `calcDamage()`，Handler接口仅 `handle()`，不强制无关方法 |
| DIP 依赖反转 | 战斗系统依赖抽象接口（DamageStrategy/EffectHandler）而非具体类 |

---

## 反AI设计要点

1. **需求故意模糊**：不明确攻击类型的完整列表、不提示装备前缀的嵌套方式、不指定效果处理机制
2. **AI天然陷阱**：每个扩展点AI倾向给出if-else/switch或深层继承方案，考生需识别并引导向设计模式
3. **验收靠证据**：强制要求测试用例和commit记录，考查考生是否验证AI输出而非盲目信任
4. **多方案各有优劣**：扩展2中的"装饰器vs继承"、扩展3中的"责任链vs顺序调用"，考生需评价AI方案优劣

## 基础任务：勇者之战

### 场景
角色可以攻击另一个角色，造成伤害并输出战斗日志。

### 故意模糊的需求（发给考生）
```
实现一个RPG战斗系统：
- 角色拥有：名字、HP（生命值）、攻击力、防御力
- 角色可以攻击另一个角色
- 伤害公式：攻击力 - 防御力，结果至少为1
- 被攻击角色HP减少对应值，HP降到0或以下视为倒下
- 每次攻击需要以可读格式输出战斗日志

预期交付：代码 + 设计文档 + 测试用例 + commit记录
```

### 故意模糊的点（等考生澄清）
- 伤害公式是否会变化？（预判扩展）
- 有哪些类型的攻击？（追问需求边界）
- 战斗流程的完整形态？（设计意识）
- 什么是"倒下"？（后续处理）
- 战斗日志格式？（国际化/可配置性）

### 设计空间（模板方法模式）
```
BattleAction.attack()
  ├── prepare()           ← 攻击前准备（装备加成、状态检查等）
  ├── calcDamage()        ← 核心钩子：伤害计算（基类：攻-防，最小1）
  ├── applyDamage(target) ← 伤害应用（HP扣除、护盾判定等）
  └── aftermath()         ← 攻击后处理（日志、倒下判定、经验分配等）
```
考生如能将攻击流程拆为模板方法并预留 `calcDamage()` 钩子，说明有设计意识。

### 评分权重（60分）
- 需求澄清与追问（18分）：是否主动澄清模糊点
- 模板方法设计（18分）：流程骨架是否合理，钩子是否足够
- 测试用例（12分）：覆盖率≥60%，正常/边界/异常
- AI交互与验证（12分）：是否review AI代码，是否用测试验证而非信任

## 扩展1（策略模式）：攻击方式

### 发给考生的描述
```
给战斗系统增加多种攻击方式：
- 普通攻击：攻击力 - 防御力（当前逻辑）
- 魔法攻击：魔力值 × 2 - 魔法防御，可穿透50%物理防御
- 暴击攻击：先判定暴击率，暴击时伤害×1.5并附带固定真实伤害

角色可以切换攻击方式，需要方便地添加新的攻击方式而不修改现有代码。

增量交付：增量设计文档 + 增量测试 + 增量commit
```

### 考察点
- 能否识别"算法族"需要策略模式封装（而非if-else/switch）
- 策略接口设计：`DamageStrategy.calcDamage(attacker, defender) -> int`
- 策略如何注入角色（构造注入 vs setter）
- 测试时是否为每个策略写了独立用例

### 反AI点
AI大概率给出 `if attack_type == "normal": ... elif attack_type == "magic": ...` 的方案。考生需要识别出这不满足OCP，引导AI向策略模式重构。

### 评分权重（20分）
- 策略模式识别与应用（10分）
- OCP验证：新增攻击方式不改现有代码（5分）
- 增量文档/测试/commit（5分）

## 扩展2（工厂+装饰器模式）：装备系统

### 发给考生的描述
```
角色现在可以装备武器和防具：
- 武器：增加攻击力（如短剑+5、法杖+8魔力）
- 防具：增加防御力（如盾牌+3、铠甲+5）
- 装备可带有特殊前缀，修改基础属性（如"火焰附魔的短剑" = 短剑+3额外攻击，"损坏的盾牌" = 盾牌-2防御）
- 装备类型和前缀的组合未来会不断新增

增量交付：增量设计文档 + 增量测试 + 增量commit
```

### 考察点
- **工厂模式**：装备创建逻辑封装为工厂（`WeaponFactory`/`ArmorFactory`），装备类型可扩展
- **装饰器模式**：前缀修改属性的本质是装饰而非继承——用装饰器包装基础装备，而非创建 `FlameSword extends Sword`
- 装饰器能否嵌套（如"火焰附魔的 受损的 短剑"）
- `calculate_attack() / calculate_defense()` 方法的递归委托正确性

### 反AI点
AI天然倾向继承——`Sword extends Weapon`, `FlameSword extends Sword`。考生需识别出类爆炸问题，引导AI走向组合/装饰器。

### 评分权重（20分）
- 工厂/装饰器模式区分与正确应用（10分）
- 装饰器嵌套正确性（5分）
- 增量文档/测试/commit（5分）

## 扩展3（责任链模式）：战斗效果处理链

### 发给考生的描述
```
战斗中增加特殊效果处理机制。攻击时按顺序检查以下环节：
- 闪避：目标有一定概率完全闪避本次攻击（不造成伤害，后续环节跳过）
- 格挡：目标有一定概率格挡，格挡成功时伤害减半
- 护盾吸收：目标若存在护盾值，优先扣除护盾，护盾耗尽后剩余伤害才扣HP
- 伤害反弹：攻击者受到最终伤害的一定比例作为反伤

效果之间的执行顺序需要灵活调整（例如某些战斗场景需要"护盾在格挡之前"），且允许未来新增效果类型。

增量交付：增量设计文档 + 增量测试 + 增量commit
```

### 考察点
- 能否识别责任链场景——每个效果是一个 `EffectHandler`，有 `handle(context)` 方法
- 链的组装方式（手动链接 vs Builder模式装配）
- 链的中断机制（闪避成功直接结束）
- 上下文对象设计（`DamageContext` 携带攻击者/目标/伤害值等状态）
- 能否不修改现有代码而新增效果类型（OCP）

### 反AI点
AI容易给出顺序调用的 `if has_shield(): absorb(); if has_dodge(): dodge()` 风格方案。考生需引导AI抽象出统一的 `EffectHandler` 接口，将硬编码转为可配置责任链。

### 评分权重（20分）
- 责任链模式识别与正确应用（8分）
- 链中断/顺序调整/新增效果（7分）
- 增量文档/测试/commit（5分）

## 整体架构图

```
基础任务（模板方法模式）
  BattleAction.attack()
    ├── prepare()           ← 子类可覆盖（装备加成计算）
    ├── calcDamage()        ← 子类可覆盖（钩子，为扩展1/2留空间）
    ├── applyDamage()       ← 子类可覆盖（HP扣除、护盾等）
    └── aftermath()         ← 子类可覆盖（战斗日志、死亡判定）

扩展1（策略模式）
  DamageStrategy.calcDamage(attacker, defender) → int
    ├── NormalStrategy
    ├── MagicStrategy
    └── CriticalStrategy

扩展2（工厂+装饰器模式）
  EquipmentFactory.create(type, prefix) → Equipment
  EquipmentDecorator(base)               ← 嵌套装饰

扩展3（责任链模式）
  BattleEffectChain.handle(context)
    ├── DodgeHandler   → 闪避判定（可中断）
    ├── BlockHandler   → 格挡减免
    ├── ShieldHandler  → 护盾吸收
    └── ReflectHandler → 伤害反弹
```
