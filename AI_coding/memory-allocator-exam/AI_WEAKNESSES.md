# AI辅助编程弱点预埋清单（面试官参考）

> 本题共预埋 **3** 个AI编程常见弱点，用于区分"真正理解系统编程的候选人"与"盲目复制AI输出的候选人"。

---

## 弱点 1：空闲链表不按地址排序 → 合并逻辑失效

**嵌入位置**：`README.md` Part 1 任务3 → 关键陷阱提示块

**AI典型行为**：
- AI假设空闲链表天然按内存地址排序
- `coalesce()` 实现为"合并链表中相邻的节点"（`curr`和`curr->next`）
- 但多次`my_malloc`/`my_free`后，空闲链表顺序已乱
- 两个物理相邻的空闲块可能在链表中间隔很远，无法被合并
- 碎片率逐渐升高，大块分配越来越容易失败

**好候选人行为**：
- 意识到链表顺序≠物理内存顺序
- 实现时先按地址重排空闲链表（O(n log n)），再合并
- 或在`my_free`时直接查找物理相邻的前后块进行合并
- 能解释为什么简单链表遍历会导致碎片累积

**检测方法**：
- 构造分配/释放序列使空闲链表顺序与地址顺序不一致
- 检查coalesce后是否真的将物理相邻块合并
- 对比碎片率：正确的coalesce应该能恢复为大块

## 弱点 2：初始化失败路径内存泄漏

**嵌入位置**：`README.md` Part 1 任务1 → 初始化要求

**AI典型行为**：
- `allocator_create()`中先`malloc(allocator_t)`，成功后再`malloc(pool)`
- 若`malloc(pool)`失败返回NULL，AI直接返回NULL，不`free(alloc)`
- 导致`sizeof(allocator_t)`字节泄漏
- 对于一次性初始化看似无害，但违反防御性编程原则

**好候选人行为**：
- 采用逐级回滚模式：每步分配失败时释放之前所有已分配资源
- 初始化代码结构清晰，错误处理路径明确

**检测方法**：
- 检查`allocator_create`中是否每个`malloc`后都有对应的错误处理
- `valgrind --leak-check=full` 应报告0泄漏
- 制造内存不足场景（`POOL_SIZE=SIZE_MAX`），检查返回值是否为NULL且无泄漏

## 弱点 3：my_free缺少指针合法性校验

**嵌入位置**：`README.md` Part 1 任务3 → 释放要求

**AI典型行为**：
- 直接对传入的`ptr`做`(block_header_t*)ptr - 1`算术
- 不检查`ptr`是否属于当前内存池`[pool, pool+pool_size)`范围
- 传入NULL、野指针、或其他分配器的指针时：静默破坏内存，难以排查

**好候选人行为**：
- `my_free`开头校验：`ptr >= pool && ptr < pool + pool_size`
- 非法指针安全忽略（或返回错误码），不崩溃
- 对NULL指针直接return（与标准free一致）

**检测方法**：
- 对已销毁的allocator调用`my_free(alloc, ptr)`不应崩溃
- 传入`(void*)0xdeadbeef` 不应产生段错误
- 检查代码中是否有地址范围校验
